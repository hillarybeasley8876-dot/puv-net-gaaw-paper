> 题目中的“结构增强”仅表示研究方向，不预设新增模块已经有效。待结构方案完成消融验证后，再依据真实机制与实验结论确定最终题目。

**文档状态**：2026-08-11 17:20 重构。

**结构依据**：标准计算机视觉方法型学位论文逻辑，而非管理学实证论文模板：

```text
研究问题与知识缺口
→ 理论基础与相关工作
→ 可复现基线及瓶颈诊断
→ 结构级方法设计
→ 对比、消融、鲁棒性与能力边界验证
→ 结论与展望
```

**全文核心因果链**：

```text
稀疏输入导致局部几何证据不足
→ 基线特征交互或重建机制出现可测量瓶颈
→ 新增结构模块针对该瓶颈建立信息通路
→ 模块改变中间表示或梯度传播的可观测量
→ CD / HD / NUC / P2F 等指标及局部误差发生变化
→ 单因素消融和失败案例界定模块的有效条件与能力边界
```

任何创新点都必须完整经过这条链。只有最终指标改善、但没有机制证据的改动，只能作为工程调优；只有机制叙述、但没有对照实验支持的改动，不进入论文结论。

## 0. 结构迁移说明

### 0.1 为什么弃用原七章管理学递进结构

原目录将“分析框架、研究假设、信度效度、主效应检验”等管理学实证论文术语映射到点云上采样研究。虽然部分内容可以对应，但会产生三类问题：

1. **研究对象错位**：本文研究对象是神经网络方法，不是潜变量、调查量表或组织机制；“信度”“效度”并非该类计算机视觉论文的标准组织方式。
2. **证据顺序倒置**：为了填满既定栏目，容易反向寻找文献和实验，削弱引用相关性。此前引用库中出现 3 条与点云上采样方法无直接关系的文献，已证明这种风险真实存在。
3. **主创新被弱化**：结构级方法创新应当集中出现在独立方法章，并由独立实验章验证；若拆散到“分析框架—研究假设—影响因素”，读者难以快速识别本文贡献。

因此改用计算机视觉方法型论文的标准结构。原有真实材料不删除，而是按证据功能重新安置。

### 0.2 原章节材料迁移关系

| 原材料 | 新位置 | 迁移原则 |
|---|---|---|
| 原第1章绪论 | 新第1章 | 保留已核实事实与引用，重写管理学式措辞 |
| 原第2章文献综述 | 新第2章 | 改为“相关理论与研究进展”，按技术问题组织，不按文献堆叠 |
| 原第3章任务定义、指标与协议 | 新第2章 2.1/2.5 + 新第3章 3.2 | 理论定义与实际协议分开 |
| 原第3章瓶颈归因 | 新第3章 3.4 | 必须绑定基线实验，不提前写成既定结论 |
| 原第4章网络结构 | 新第3章基线 + 新第4章改进方法 | 基线结构与本文新增结构严格区分 |
| 原第4章 GAAW | 新第4章辅助训练策略或附录消融 | 不再作为结构级主创新；是否进入正文由后续实验决定 |
| 原第5章信度/效度 | 新第3章协议核验 + 新第5章指标标定 | 换成计算机视觉通用术语 |
| 原第5、6章实验 | 新第5章 | 合并为统一实验章，避免结果被人为切碎 |
| 原第7章 | 新第6章 | 改为结论、局限与展望 |

### 0.3 当前研究决策

- **主性能提升来源**：新增结构级改进；具体结构、名称和贡献表述待真实实验定型。
- **GAAW 定位**：训练辅助机制。B1/B2/BD 暂停，待结构方案定型后决定是否恢复；若贡献有限，降级为附录消融。
- **B-002 baseline150**：继续跑完，作为结构改进的统一对照基线。
- **微调组定位**：双向 CD 权重、均匀性权重、注意力缩放等不作为主创新；仅用于控制变量、实现核验或附录敏感性分析。
- **结论纪律**：结构方案未完成实验前，正文只写设计动机、定义和验证计划，不写“显著提升”“有效解决”等结果性表述。

### 1.1 字数控制原则

- 第2章不扩写为 11,000 字。综述只服务于问题定义、结构选型和实验对照，避免挤占方法与实验章节。
- 第4、5章是全文主体，合计约 22,500 字，占正文近一半。
- 字数不足时，补充公式推导、实现细节、协议说明、机制证据和失败案例，不补常识性背景。
- 字数超过 50,000 时，优先压缩第1、2章的重复综述，不压缩结构消融、鲁棒性与失败案例。

### 1.2 图表原则

- 一图一论点；图题直接说明该图证明什么。
- 网络图必须同时给出张量形状、信息流向和模块边界。
- 机制图必须区分“设计示意”与“实验结果”；示意图不冒充实验证据。
- 实验图必须链接真实源数据、生成脚本和口径说明。
- 不依赖颜色表达唯一信息；灰阶打印仍可辨认。
- 不追求装饰性排版，优先保证过程完整、局部可读和信息密度。

## 4. 写作与证据纪律

1. **实验数字唯一出口**：论文主表数字来自官方评价函数；训练期 `monitor_*` 仅用于训练动态图和选点分析，并显式标注“非论文主表口径”。
2. **未完成实验使用 TBD**：不得填写估计结果、预计提升或虚构趋势。
3. **结果与解释分开**：先报告观测值及不确定性，再讨论可能机制；不得把相关性直接写成因果性。
4. **结构创新最小消融**：完整模型、移除模块、模块内部组件、插入位置、复杂度增量五类证据缺一不可。
5. **负面结果完整保留**：无效、退化、冲突和不确定结果进入第5.8节或实验附录，不隐藏、不筛选。
6. **引用证据绑定**：引用必须来自 `docs/REFERENCES.json` 的已核实条目；正文先用 `{{cite:KEY}}` 占位，不凭印象写编号。
7. **引用必要性检查**：每条引用必须支持所在句子的具体事实、机制或对比；若删除引用后句子仍完整成立，则该引用属于装饰性引用，应删除。
8. **图表可追溯**：每张实验图必须有真实数据源和生成脚本；机制示意图必须标明“示意图”或在元数据中声明 `depends_on_experiment`。
9. **术语统一**：数学符号、中英文术语及指标缩写以 `docs/STYLE_GUIDE.md` 为唯一依据。
10. **结论范围受证据约束**：只对已测试的数据集、倍率、噪声范围和评价协议作结论；不外推到未测试场景。
11. **库容量变动后迁移编号**：使用 `scripts/migrate_cite_numbers.py` 按 key 映射迁移，禁止手工批量改引用数字。
12. **章节成稿自检**：引用、数值、图表、方法—结果对应关系和 TBD 状态全部通过检查后，章节才可标记为成稿。

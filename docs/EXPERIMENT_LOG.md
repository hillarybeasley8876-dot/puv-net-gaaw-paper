## D1-001-v1 — CD 密度失衡敏感性【设计错误·作废】

```yaml
exp_id: D1-001-v1
date: 2026-08-10
category: 构造实验
status: 作废（设计错误，非硬件/环境问题）
supersedes_by: D1-001-v2
script: scripts/exp_d1_cd_blindspot.py
seed: 20260810
machine: 本机 RTX 3090 24G（纯 CPU/numpy 计算，未用 GPU）
```

### 作废原因（必须留档，防止重犯）

两个对照构型的**误差预算不对等**：

- `make_uniform` 扰动**全部** 8192 点 → 每点带 jitter 误差，CD 地板 ~10e-3
- `make_clumped` 只扰动 frac 比例的点，**其余点精确压在 GT 上** → 对 CD 贡献 ~0

实际测量的是「扰动了多少比例的点」，不是「CD 能否感知密度失衡」。

**自相矛盾的实测证据**：塌缩 10%（劣化构型）CD = 3.8504e-3，
反而比均匀构型 10.0296e-3 **好 2.6 倍**。对照组逻辑上不成立。

### 附带发现的流程缺陷

脚本按 `max(nuc_rel/cd_rel)` 挑一行后**无条件打印**「CD 存在结构性盲区，
这为引入对抗约束提供机制性依据」——即使数据中有一行直接反驳前提。
**这是给修辞加了个 print，不是实验。**
→ 已定为流程铁律：判据必须跑前写死，脚本不得输出超出判据的解释性结论。

### 结论

v1 全部数字作废，**不得进入论文**。

## D1-001-v2 — CD 密度失衡敏感性（对齐误差预算）【判据未通过】

```yaml
exp_id: D1-001-v2
date: 2026-08-11
category: 构造实验
status: 已完成（判据 FAIL，如实记录）
script: scripts/exp_d1_cd_blindspot_v2.py
result: runs/D1v2_cd_blindspot/result.json
seed: 20260810
n_points: 8192
perturb_frac: 0.50
machine: 本机（numpy/scipy，未用 GPU）
preregistered: true
```

### 设计（相对 v1 的修正）

两构型严格对齐：**相同 idx、相同位移幅度 step**，唯一差别是方向
——U = 切平面随机方向（散开，保持均匀）／C = 指向最近邻（塌缩，制造聚集）；
两者均投回单位球面。目的：把 CD 构造性地held住，令 NUC 成为唯一自由变量。

### 预注册判据（跑前写死，见脚本 CD_TOL / NUC_MIN_RATIO）

- **P1**：`|cd_C/cd_U - 1| <= 0.10`
- **P2**：`nuc_C/nuc_U >= 3.0`
- 两者同时满足（任一 step 档位）→ 支持 RQ1；否则 → 不支持，且不得改判据重试。

### 实测结果（原样抄录，×10⁻³ 为 CD/HD 单位）

| step | CD_U | CD_C | CD比值 | NUC_U | NUC_C | NUC比值 | P1 | P2 |
|------|------|------|--------|-------|-------|---------|----|----|
| 0.005 | 4.99995 | 4.99954 | 1.000x | 0.000694 | 0.000641 | 0.92x | PASS | fail |
| 0.010 | 9.99963 | 9.99974 | 1.000x | 0.000828 | 0.000897 | 1.08x | PASS | fail |
| 0.015 | 14.99873 | 15.00031 | 1.000x | 0.001072 | 0.001263 | 1.18x | PASS | fail |
| 0.020 | 19.74969 | 18.25853 | 0.924x | 0.001325 | 0.001729 | 1.30x | PASS | fail |
| 0.030 | 20.09170 | 13.47026 | 0.670x | 0.001891 | 0.003419 | 1.81x | fail | fail |

**总判定：FAIL**（无任何档位同时满足 P1 与 P2）

### 结论（严格限定在本 run 能支撑的范围）

1. **P1 稳定成立**：step ≤ 0.015 时 CD 比值精确到 1.000x。
   位移幅度对齐后，两构型每点到 GT 的最近邻距离均等于 step
   → **CD 对「位移方向」完全不敏感**，这一点成立。
2. **P2 全线不通过**：NUC 比值最高仅 1.81x（门槛 3.0）。
   预想的「CD 无差别而均匀性数量级恶化」情形，**在本构造下未能造出**。
3. NUC 比值随 step 单调上升（0.92 → 1.81），趋势方向正确但强度远不足。

### 已知构造局限（关键，决定结论的解释边界）

读 result.json 发现：step ≤ 0.015 时 **`cd_u` 与 `hd_u` 数值完全相等**
（如 0.004999953125756854 vs ...947，仅差浮点末位）。CD 与 HD 撞值暴露出：
被扰动点位移幅度**严格定长**、未扰动点误差为 0，故「平均最近邻距离」
与「最大最近邻距离」必然重合。

推论：定长位移 + 投影回球面，使塌缩点停在最近邻**旁边**而非**重合**，
本构造**从机制上就不产生真正的多点共位聚集**，而这正是密度失衡的本质。

→ 因此 FAIL 的成因是**两者混合**：
   ① 假设可能不成立；② 构造仍不足以检验该假设。
   二者结论截然不同，**本实验无权判定「CD 不存在盲区」**。

### 本 run 明确**不能**得出的结论

- ❌ 不能说「CD 没有密度失衡盲区」（构造局限见上，检验力不足）
- ❌ 不能说「引入对抗/均匀性约束无效」（本实验与之无关）
- ❌ 不能反向说「CD 有盲区」（P2 未通过，无证据）
- ❌ NUC 绝对值不得与文献对表（简化实现，仅本实验内相对比较）

### 对论文的直接影响

论文原计划第 3 章以 D1 打头，用「CD 盲区」建立机制性叙事。
**该叙事现无数据支撑，按预注册约定必须删除。**
创新点定位改为由 **B 组消融的经验结果**说话（加入均匀性/对抗约束后
CD/HD/P2F/NUC 是否真的更好），结果好坏均如实报告。

## ⚠️ 指标协议修正（2026-08-11）—— 影响所有既往 CD/HD 数字

**本项目原先的 CD/HD 实现与 PU-GCN 官方协议不一致，已修正。此前所有 CD/HD 数值一律作废。**

### 错误是怎么产生的

`puvnet/metrics/pointcloud.py::chamfer_distance` 原先默认 `squared=False`（L2 距离），
并在 docstring 里写：

> ⚠️ 本项目主表统一用 squared=False（L2 距离），与 PU-GCN evaluate.py 一致。

**这条注释未经核实，且是错的。** 它导致 E-000 v1 的所谓"作弊上界" CD=11.39e-3
比文献 SOTA 0.451e-3 差 25 倍，一度被误判为管线 bug 或数据问题。

> **教训（已升级为流程铁律）**：注释里写「与某官方实现一致」属于**事实声明**，
> 必须附一手出处；否则它会让后来所有人不再去查，是最危险的一类错误。
> 凡涉及"与文献/官方对齐"的声明，必须在 `refs/` 下留一手代码快照 + sha256。

### 一手代码核实结果

已从 GitHub 拉取 `guochengqian/PU-GCN` (tree sha `0a8daac5…`) 并落盘存证：

- 分析：`refs/pu_gcn/CD_PROTOCOL_SOURCE.md`
- 源码快照 + sha256：`refs/pu_gcn/snapshot/`（5 个文件，`MANIFEST.json`）

| 项 | 原实现（错） | 官方协议（一手确认） | 出处 |
|---|---|---|---|
| CD 距离本体 | L2（开方） | **平方距离** | `tf_nndistance_cpu.py`: `reduce_sum(pc_diff**2)` 无 sqrt |
| CD 聚合 | 双向 mean 求和 | 双向 mean 求和 ✅ | `evaluate.py`: `CD = mean(fwd)+mean(bwd)` |
| HD 距离本体 | L2（开方） | **平方距离** | `Common/metrics.py` 输入即上述平方距离数组 |
| HD 聚合 | max(两方向 max) ✅ | max(两方向 max) | `metrics.py` docstring 明确「不是相加」 |
| 评测归一化 | 共享 gt 的 center/scale | **pred/gt 各自独立** | `evaluate.py` 两次调 `normalize_point_cloud`，返回值未复用 |
| P2F 距离/坐标系 | L2 / 归一化后 | L2 ✅ / **原始尺度** | `evaluation_code/evaluation.cpp` 直读 .off 与 .xyz，无归一化 |
| Uniformity | 简化欧氏版 | CGAL 测地 disk + coverage×spacing | `evaluate.py::analyze_uniform` |

另确认两件事：
- **`evaluation.cpp` 只算 P2F**，不算 CD/HD/uniformity（曾误以为 CD 出自 C++ 侧）。
- 官方 `normalize_point_cloud`（`Common/ops.py:599`）= 质心中心化 + 除最远点距离，
  与本项目实现**逐行一致**，这一处原本就对。

### 训练 vs 评测 的归一化差异（易混，务必区分）

| 阶段 | 做法 | 理由 |
|---|---|---|
| **训练**（`puvnet/data/pu_dataset.py`） | input 与 gt **共享 gt 的 center/scale** | 不共享则监督信号本身错位；已由 dataset 自检 [6] 用 CD 对照验证 |
| **评测**（`scripts/evaluate.py`） | pred 与 gt **各自独立**归一化 | 官方协议如此，为对表必须照做 |

### 修正后的验证

`puvnet/metrics/pointcloud.py` 自检 **8/8 PASS**，其中新增两项是关键：

- **[6] 与官方 `nn_distance` 语义的逐行 numpy 参照实现对比**：
  CD 差 `0.00e+00`，HD 差 `1.78e-15` → 数值层面完全一致。
- **[7] `eval_cd_hd_official` 缩放不变性**：pred 单独 ×100 再平移 +7，
  CD 相对变化 `1.92e-15` → 证实"各自独立归一化"已落实。

`scripts/evaluate.py --self-check` **6/6 PASS**，量纲已回到文献档位
（抖动上采样 CD=0.3025e-3，此前 L2 协议下为 17~30e-3，差约 50 倍）。

### E3 FAIL 的根因：判据前提不成立，非管线 bug

`jitter_large`(σ=0.02) 的 CD 反而**优于** `jitter_small`(σ=0.005)。
用 `exp_e000_aux_jitter.py` 把 CD 拆成双向分项后机理明确（8 模型，整模型原始坐标系加噪）：

| σ | fwd (pred→gt，精度项) | bwd (gt→pred，覆盖项) | CD | bwd 占比 |
|---|---|---|---|---|
| 0.0000 | 0.226942 | 0.650673 | 0.877615 | 74.14% |

观测事实：
1. **fwd 严格单调递增**（0.2269 → 21.63）→ 噪声确实在破坏精度，**管线行为正常**。
2. **bwd 先降后升**，在 σ≈0.005 触底（0.4267 vs σ=0 的 0.6507）→ 抖动把 4 份重合点散开，
   **改善了 GT 覆盖**。
3. 两个相反作用叠加 → CD 在 **σ=0.0025 出现内部极小值**，本质**非单调**。
4. σ=0 时 bwd 占 CD 的 **74.14%** —— 复制型上采样的误差主要来自覆盖缺失，而非精度。

**结论：E3 判据把"噪声单调恶化"当作前提，但该前提在复制型基线上不成立。**
复制上采样有大量共位点，噪声兼具「破坏精度」与「改善覆盖」两种相反作用。
这是被测对象的真实性质，不是实现缺陷。

> **处理方式（不改判据让它通过）**：E3 判定为 **FAIL 且判据本身设计不当**，
> 保留 FAIL 记录不掩盖。后续如需检验噪声单调性，应针对 **fwd 分项**预注册新判据
> （已实测 fwd 严格单调），而非总 CD。**不追溯修改 E3 使其"通过"。**

### 顺带发现的可比性陷阱（重要，已写入代码注释）

主实验 `jitter_large`(σ=0.02) CD=1.123，而附属诊断同 σ=0.02 却是 3.696，**差 3.3 倍**。
原因：主实验的 `Jitter` 参照器加噪发生在 **patch 归一化坐标系**内

## 🎯 创新点定位定案（2026-08-11）

### 用户拍板

1. **定位 = 硕士学位论文（工程改进型）** —— 不新增结构级模块，不追投顶刊
2. **M1 = 主创新，B1+B2 必须跑**（5090 约 26 h / 65 元）

### 代码核实：创新点到底存在什么（`scripts/show_ablation_changes.py`）

先说**不是**创新点的部分，避免日后自我夸大：

| 相对 | 实际改动 | 定性 |
|------|----------|------|
| PU-Transformer | 主干结构**零改动**（SC-MSA + Shifted Channel Attn + shuffle 头，1,152,803 参数，纯复现） | 复现 |
| PU-Transformer | D1：SC-MSA 的 QK^T 加 `1/sqrt(d)` 缩放（`pu_transformer.py:289`） | **实现细节**，标准 Transformer 常规做法，原文未写清；做成开关是为消除混杂因子，**不作为创新点** |
| PU-GAN | B1：固定权重对抗（`w_adv=8.27`） | 照搬 |
| PU-GAN | C1：uniform 损失项（`w_uniform=0.00191`） | 照搬 |

**真正属于本文的两条：**

| 编号 | 内容 | 原创性依据 |
|------|------|-----------|
| **M1**（B2 组） | **梯度范数自适应对抗权重**：每步实测 \|g_adv\|/\|g_CD\|，动态调 `w_adv` 使比值稳定在 `adv_target_ratio=0.1` | PU-GAN 原文为固定权重。本文实测：`w_adv=1.0` 时对抗梯度仅为 CD 的 **1/82.65**，即"名义开了 GAN、实际等于没开"——该失效模式此前未见报道 |
| **A**（A1 组） | **双向 CD 非对称加权**：实测 bwd 项长期占 54.46%（B-001 全程 >0.5，min 0.5285 / max 0.5678，无交叉），按贡献比反配权重把 fwd 拉回 0.5 | 未见有文献报告该长期不对称现象及其纠正 |

### ⚠️ 诚实边界（必须写进论文，不得隐去）

- 两条创新**均在损失函数层面**，本质是 loss reweighting 的自动化，**不是网络结构创新**
- 审稿人可合理质疑「这不就是 loss reweighting」——论文应正面回应：贡献在于
  **给出失效的量化证据（1/82.65）与可自动校正的机制**，而非声称提出新算子
- 该创新强度与「工程改进型学位论文」定位匹配；**不足以支撑顶刊投稿**，这是主动
  选择的定位，不是掩饰

### B1 为何不可省（跑前写死）

M1 的结论必须能区分两件事：
- 「引入对抗」本身带来的增益 → 由 **B1（固定 `w_adv=8.27`）** 测
- 「自适应机制」额外带来的增益 → 由 **B2 − B1** 测

若只跑 B2，任何增益都无法归因到 M1，主创新即不成立。故 **B1 是 M1 的必需对照，
不是可选项**。

- **推理期逐样本 HD（n=200）**：cv 约 0.48-0.51，p90/p10 约 2.9-3.2 倍，**无一个样本超过 5x 中位数**。分布温和，无离群尖峰。
- **训练期逐 epoch `monitor_hd`（n=150）**：无对抗组 cv = 0.135(B0-3090) / 0.186(B0-5090) / 0.157(C1)；**对抗组 cv = 0.397(B1) / 0.412(B2)，约为无对抗组的 2.5 倍**。按 `>2x 中位数` 计尖峰：B0-3090 0 个、C1 1 个(ep77)、B0-5090 2 个(ep1/147)、**B1 4 个(ep110/111/126/128)**、**B2 3 个(ep76/104/144)**。

结论修正为：**HD 的波动主要出现在训练期 epoch 间，且与对抗分支的引入相关；推理期逐样本分布并无离群尖峰。** 原先「偶发尖峰」的说法指向的是训练期现象，不可用来解释推理期主表的 σ。

**② 尖峰阈值属事后选定，只能作描述性统计。** 以 `5x 中位数` 为界时 5 个 run 合计只剩 1 个点，无法支撑「对抗组波动更大」的比较；改用 `2x 中位数` 后各 run 计数 0/1/2/4/3 可比。该阈值在观察数据后选定，故图注明写**尖峰计数为描述性统计，不作为假设检验结论**。

### 1.8 两条原创改进的实测动因（代码级核实）

创新点核实结论：相对 PU-Transformer 主干**零结构改动**（纯复现 1,152,803 参数）；
`scale_qk`（D1 组）是实现细节非创新点；B1 固定权重对抗与 C1 uniform 项均照搬 PU-GAN。
**真正原创只有下面两条，且均在 loss 层面。**

| 编号 | 改进 | 实测动因（本项目自有数据） | 出处 |
|---|---|---|---|
| **M1** | 梯度范数自适应对抗权重（B2 组） | `w_adv=1.0` 时对抗梯度仅为 CD 梯度的 **1/82.65**（实测 `w_auto=8.27`）→ 固定权重下对抗项近乎无效 | `puvnet/losses/upsampling.py` 自检 16/16 PASS |
| **A** | 双向 CD 非对称加权（A1 组） | 反向 CD 长期占总 CD 梯度的 **54.46%**（min 52.85% / max 56.78%，全程无交叉）→ 前后向天然不均衡 | B-001 `cd_bwd_share` 全程记录 |

A1 的加权系数由 `scripts/calibrate_improve_a.py` 从实测占比反解得出：
A1 均衡化 `(w_fwd, w_bwd) = (1.078971, 0.921029)`；A2 反向对照 `(0.921029, 1.078971)`。
**已验证默认值与原始对称 CD 逐位等价（diff = 0.0e+00）**，即改进 A 不引入实现漂移。

**C1（uniform 项）的自有量化依据**（`scripts/build_cloud_comparison.py` 实测）：
GT 最近邻距离变异系数 `nn_cv = 0.0507`，baseline 预测 `nn_cv = 0.2444`，**差 4.82 倍**
→ 复现基线的点分布均匀性确实显著差于 GT，uniform 项有明确的待修复缺陷可打。
（此前依据仅是「PU-GAN 原文有这一项」，属他人论文；现已有本项目实测支撑。）

**诚实边界**：M1 与 A 本质都是 loss reweighting 的自动化，**不足以支撑顶刊**。
论文定位已据此定案为**硕士学位论文（工程改进型）**，不追顶刊、不新增结构级模块。

### 1.10 参考文献真实性核实（2026-08-11 16:05）

**背景**：论文要求 70+ 篇真实可查文献。大模型编造文献（幻觉标题 / 编造 arXiv ID / 张冠李戴）
是学术不端，本项目对此建立**逐条 API 核实**机制，不靠记忆、不靠搜索引擎摘要。

**核实工具链**（三个脚本，均已跑通）：

| 脚本 | 字节数 | 作用 |
|---|---|---|
| `scripts/verify_refs.py` | 12,127 | 逐条打官方 API 核实，输出 ACCEPTED / REJECTED 两份 |
| `scripts/merge_refs.py` | 5,031 | 多批合并 + 标题归一化去重 + 统一编号 |

**核实通道**（四条，按优先级）：
1. arXiv Atom API — `export.arxiv.org/api/query?id_list=`
2. Crossref — `api.crossref.org/works/<DOI>`
3. DBLP — `dblp.org/search/publ/api`（**本次实测持续 503，不可用**）
4. OpenAlex — `api.openalex.org/works?filter=title.search:`（DBLP 挂掉后的有效兜底）

**判定规则**（跑前定死，写在脚本里）：
- 标题匹配：归一化后相等 / 一方包含另一方 / token-Jaccard ≥ 0.8
- 年份容差：±1 年（容忍 preprint 与会议年差异）
- 任一条核不到 → 进 `REF_REJECTED_*.json`，**绝不留在引用库里**

**核实器自身的有效性验证**（这一步不能省）：
用 5 条真实 + 2 条故意伪造的样本先验核实器本身——
- 编造的 arXiv ID `2409.99999`（假论文 PU-HyperFormer）→ 正确判 `arxiv_no_entry` ✅
- 把 PU-GAN 的标题篡改成幻觉标题、ID 保持真实 → API 返回真标题，正确判 `title_mismatch` ✅
- 编造标题 `PU-QuantumFlow: Entangled Manifold Upsampling` 走 OpenAlex → 正确判 `no_hit` ✅
→ 核实器能抓假货，结论可信。

🟠 **补充教训（2026-08-11，RepKPU 复核）**：`title_mismatch` 有两种成因，处置方式相反——
**① 论文不存在**（须弃用）；**② 论文真实但候选记录里的 ID 填错**（须换检索通道重核）。
RepKPU 属第 ② 类：候选记录写的 `arXiv:2403.10962` 实际指向另一篇 SP-GAN 论文，
而 RepKPU 本身**根本没有 arXiv 预印本**，只有 CVPR 2024 正式版

### 3.1 参数量差距 18.9%

不隐藏。论文写法：「本文复现版参数量 1.15M，原文报告 0.97M。
差异源于原文未公开代码，SC-MSA 输出投影层与 PosFus 内 MLP 的具体配置无法逐层核对。」

### 3.2 baseline 是「本文复现」而非官方实现

用户已确认「全部自己跑」。PU-Net / PU-GAN 原为 TF 1.x，本项目用 PyTorch 复现。
**论文中必须逐项标注**：
- 「本文复现」→ 报告复现值，并与原论文值对比说明差距
- 「官方实现 + 官方权重」→ Grad-PU / RepKPU 若采用此路径
- 「文献引用」→ 无法复现的方法

**绝不允许把复现不到的数字抄原论文然后声称是自己跑的。**

### 3.3 创新点的时间位置劣势

本方法 = PU-Transformer(2022 ACCV) + PU-GAN(2019 ICCV)，
而 Grad-PU(2023 CVPR)、RepKPU(2024 CVPR) 已在同 benchmark 更强。

**主表可能打不过 RepKPU。** 这是客观事实，不是可以靠写作技巧绕过的。
可辩护方向（须实验支撑，见 SOTA_SURVEY §6）：机制性解决融合矛盾、噪声鲁棒性、
训练稳定性、参数量/速度权衡。

**如果实验证明本方法全面落后，我会如实告诉你，不会替你美化。**

### 3.4 NUC 为简化实现

以已有点为 disk 中心，非 mesh 表面泊松撒点。**只能做方法间相对比较，不能与文献绝对值对表。**
若论文需报绝对值，须改用 mesh 表面采样版本。
